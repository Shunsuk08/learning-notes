1スタック
メソッドを呼ぶたびにフレームが積まれ、終わると消える。ローカル変数（プリミティブの値・参照の値）が入る。
2ヒープ
newで作ったオブジェクト本体が置かれる。どこからも参照されなくなるとGCが回収する。
3Javaは常に値渡し
参照型は「参照の値」がコピーされる。中身の変更は呼び出し元に見えるが、再代入は見えない。
void change(List<String> l, String s) { l.add("x"); // 呼び出し元に見える s = s + "1"; // 呼び出し元は変わらない }
4共有と並行性
Springのbeanは既定でシングルトン（1個）。複数リクエストのスレッドが同じオブジェクトを使うので、フィールドに処理中の値を持つと他人の値と混ざる。staticも同じ。
52種類のメモリ不足
StackOverflowError：再帰が深すぎてスタックが溢れる。OutOfMemoryError：ヒープ不足（大量データを一度にListに読み込む等）。
6レビューの着眼点
beanのフィールドに状態を持っていないか。10万件を一度にメモリに載せていないか（ページング・ストリーム処理）。
💡変数に入っているのは参照。「その実体を誰と共有しているか」を意識すると、値渡し・並行性・GCが一本の線で繋がる。
