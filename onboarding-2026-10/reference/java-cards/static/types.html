型システムとキャスト

「型不一致」のレビュー指摘を自分で見つけられるようになる
1プリミティブ型
int/long/double/boolean/char等。値そのものを保持する、最も基本的な型。
int count = 10; double price = 99.9; boolean ok = true;
2参照型
String/配列/クラス等。実体への「参照（住所）」を保持する。
String s = "abc"; int[] a = {1,2,3}; TaxService svc = ...;
3ラッパー型とオートボクシング
intのラッパーはInteger。自動変換されるが、==比較で罠になる（-128〜127だけキャッシュされ同一視される）。
Integer a = 100, b = 100; a == b; // true（罠） Integer c = 200, d = 200; c == d; // false（罠）
4キャスト（明示的変換）
大きい型から小さい型への変換は明示が必要。情報が失われることがある（桁あふれ）。
double d = 3.9; int i = (int) d; // 3（切り捨て）
5お金をdoubleで計算する罠
doubleは2進数で誤差が出る。金額計算はBigDecimalを使う（比較はcompareTo）。
0.1 + 0.2 == 0.3; // false new BigDecimal("0.1") .add(new BigDecimal("0.2"));
6型不一致レビューの着眼点
引数の型が呼び出し先と合っているか、暗黙の変換で精度が落ちていないかを確認する。
💡「数値がおかしい」バグの多くは型の取り違え。金額はBigDecimal、比較はcompareTo、が基本。
