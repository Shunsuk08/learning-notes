プログラムの実行の流れ

.java を書いてから、動くまでに何が起きているか
Demo.java
人間が読めるソース
→
javac
コンパイラ
→
Demo.class
バイトコード
→
(任意) jar
classの束
→
java
起動コマンド
→
JVM 実行
結果を出力
1.java → .class
javac コンパイラが、人間向けのソースコードを JVM 専用の中間言語「バイトコード」に変換する。拡張子は .class。
2JVMの役割① OS差異の吸収
Windows / Mac / Linux で違う部分を JVM が吸収する。同じ .class ファイルがどのOSでも同じように動く。
3JVMの役割② メモリ管理
ガベージコレクション（GC）が不要になったメモリを自動で解放。開発者が細かくメモリを意識しなくてよい。
4jar ファイル（任意）
複数の .class をまとめて1つの圧縮ファイルにする。開発中はやらないことも多いが、リリース時はほぼ必須。
💡 実行の正体は、javacでバイトコードを作り、javaコマンドでJVMに渡して動かすこと。
