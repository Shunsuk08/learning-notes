文字列と等価性

==とequalsの取り違えは、Javaで一番多いバグの入口
1String はイミュータブル
一度作った文字列は変更できない。「変更」に見える操作は新しいStringを作っている。
String s = "a"; s = s + "b"; // 新しいStringを生成
2== は参照の比較
==は「同じ実体か」を見る。値が同じでも実体が違えばfalseになりうる。
new String("a") == new String("a"); // false
3equals は値の比較
文字列・業務オブジェクトの「中身が同じか」はequalsで比較する。
"a".equals(s); // 値を比較 // null比較はこの向きが安全 "未登録".equals(owner);
4equalsとhashCodeはセット
equalsを実装したらhashCodeも実装する。忘れるとHashSet/HashMapで別物扱いされる。
5StringBuilder
文字列をループで繰り返し連結するときは、毎回新規生成されるString連結ではなくStringBuilderを使う。
StringBuilder sb = new StringBuilder(); sb.append("a").append("b");
6レビューの着眼点
文字列・業務オブジェクトの比較に==が使われていないか。nullが来うる側をequalsの左に書いているか。
💡==は「同じ箱か」、equalsは「中身が同じか」。業務ロジックの比較はほぼ常にequals。
