null安全性と Optional

NullPointerExceptionは、Javaで最もよく遭遇する実行時エラーの一つ
1nullとは
「何も指していない」参照。nullのメソッドを呼ぶとNullPointerException（NPE）になる。
2null比較の向き
nullになりうる変数をequalsの左に書くとNPEになる。定数・リテラルを左に書くのが安全。
owner.equals("未登録"); // ownerがnullでNPE "未登録".equals(owner); // 安全
3Optionalとは
「値があるかもしれないし無いかもしれない」ことを型で表現する箱。戻り値に使う。
Optional<User> find(Long id) { return repo.findById(id); }
4Optionalの使い方
isPresentで存在確認、orElseでデフォルト値、mapで中身を変換する。
find(id).map(User::getName) .orElse("未登録");
5アンチパターン
Optional.get()をいきなり呼ぶのはnullチェックを素通りしているのと同じ。フィールドや引数にOptionalを使うのも非推奨（戻り値専用）。
6レビューの着眼点
DBから取得した値を未チェックで使っていないか。所有者未登録のような「任意項目」のnullを想定しているか。
💡「null かもしれない」と気づけるかが全て。戻り値の型がOptionalか素の型かで、呼び出し側の扱いが変わる。
