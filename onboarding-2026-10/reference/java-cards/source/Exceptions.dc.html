例外処理

「異常系をどう設計するか」はレビューで一番問われるところ
1try-catch-finally
tryで例外が起きうる処理、catchで対応、finallyは成否に関わらず必ず実行される。
try { risky(); } catch (IOException e) { ... } finally { close(); }
2チェック例外
IOException等。呼び出し元でcatchかthrowsが必須。コンパイラが強制する。
void read() throws IOException { ... }
3非チェック例外
RuntimeException系。引数の不正はIllegalArgumentException、業務エラーもこちら側で作るのが一般的（TERASOLUNAならBusinessException）。
throw new IllegalArgumentException( "税額が範囲外: " + amount); // TERASOLUNA: BusinessException // → RuntimeExceptionの子孫
4使い分けの目安
呼び出し元が「回復できる」ならチェック例外、「プログラムの誤りに近い」なら非チェック例外。
5try-with-resources
AutoCloseableを実装したリソースを自動でcloseしてくれる。finallyでcloseを書く手間とリークを防ぐ。
try (InputStream in = ...) { ... } // 自動でclose()される
6@Transactionalとの関係
非チェック例外（RuntimeException）はデフォルトでロールバックされる。チェック例外はロールバックされない点に注意。
💡例外設計のレビューは「握りつぶしていないか」「ロールバックされる種類の例外か」の2点をまず見る。
