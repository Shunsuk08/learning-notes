アノテーションの3つの用途

@マークだけ見ても分からない理由は、「誰が読み取るか」が3通りあるから
1情報提供
読む人：開発者・IDE
ソースコードを見る人への注釈。プログラムの動作には影響しない。IDEが打ち消し線を出し、javacもコンパイル時に警告を出す。
// 打ち消し線＋警告が出るだけ @Deprecated void oldMethod() { ... }
2コンパイラによる利用
読む人：コンパイラ
アノテーションプロセッサがソースを解析し、classファイルにコードを追加・修正する。ソースには無いメソッドが class 側にだけ存在することがある（例：Lombok）。
@Getter class User { String name; } // classには getName() が自動追加
3プログラムによる利用
読む人：実行時（リフレクション）
実行中にリフレクションでアノテーションを検査し、動作を変える。型安全性が落ちるため慎重な利用が必要。SpringのDIコンテナが典型例。
@Component class TaxService { ... } // DIコンテナが自動でnew&管理
💡 @アノテーションだけ見ても動きは分からない。「IDE／コンパイラ／実行時リフレクション」のどれが読み取るかで意味が決まる。
